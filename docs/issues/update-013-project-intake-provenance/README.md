# update-013: プロジェクト側の update 案件でも取り込み時に「経緯と目的」を精査する規定を `template/CLAUDE.md` に追加

## ステータス

Closed（2026-09-07 起票・完了。Codex レビュー2回で高・中ゼロ収束〔codex-01（A、ゼロ）→ `/new` → codex-02（C、ゼロ）〕、人レビュー承認済み、design.md どおり反映・検証済み）

## 概要

update-012 は「テンプレート側が他リポジトリから取り込むとき」の経緯と目的の精査をルート `CLAUDE.md` に入れ、
`template/CLAUDE.md` には「プロジェクト側が経緯を記録する義務」だけを入れた。その結果、**プロジェクト側がテンプレート
（または他リポジトリ）から取り込むとき**の精査規定が欠けている。本案件は `template/CLAUDE.md`「ドキュメント更新フロー」の
ステップ2・3 に、ルート `CLAUDE.md`「テンプレート改訂フロー」ステップ2・3 と同じ精査・記録の規定を、プロジェクト向けに読み替えて追加する。

| # | 対象 | 変更 |
|---|---|---|
| 1 | `template/CLAUDE.md`「ドキュメント更新フロー」ステップ2 | テンプレート取り込み（および他リポジトリの運用の取り込み）で、反映元の案件フォルダの文書（README の背景・採らなかった案・人レビューの記録、design の改訂履歴、reviews）を読んで経緯と目的を精査し、候補ごとに (a) 契機 (b) 目的 (c) 形式の理由 (d) 保持すべき制約 (e) 典拠 を記録する。確認できない候補は推測で補わずユーザーに確認するか取り込まない |
| 2 | 同 ステップ3 | 反映元の文面を本プロジェクト向けに読み替える置換は、1件ごとに変更前・変更後と (d) を損なわない理由を design.md に書く |

## 背景・変更理由

### 契機（2026-09-07、update-012 完了直後の人レビュー）

ユーザーの問い「`取り込み時の経緯と目的の精査を必須化`、これ、update 案件で使うようにテンプレートはなっているのか？」に対し、
`template/CLAUDE.md` を確認したところ、ステップ2 のテンプレート取り込みの規定は「反映元パス・コミットID・差分の全量と、取り込む/取り込まない の選別と理由を書く」までで、
反映元（テンプレート側）の案件文書を読む義務がなかった。update-012 は還元方向（プロジェクト → テンプレート）の精査と、プロジェクト側の記録義務を整えたが、
取り込み方向（テンプレート → プロジェクト）の精査を入れ忘れていた。方向が逆なだけで、update-011 で Claude Code が反映元の経緯を読まずに誤った提案をした失敗と同じ構造が
プロジェクト側に残る（例: lift2d が本リポジトリの update-011 を取り込む際、`reviews/` の経緯を読まずに逆還元候補3件の文面差を「テンプレートの誤り」と判断しうる）。

### 目的

- プロジェクト側の update 案件でも、テンプレート（および他リポジトリ）からの取り込みを、反映元の目的に照らして選別・読み替えできるようにする
- 「経緯が分からないものは取り込まない」をプロジェクト側にも規則化し、推測で目的を補うことを禁止する
- ルート `CLAUDE.md` とテンプレートで精査の規定を対称にし、還元・取り込みのどちらの方向でも典拠を辿れるようにする

### 形式の理由と採らなかった案

| 案 | 内容 | 判断 | 理由 |
|---|---|---|---|
| **採用** | ルート `CLAUDE.md` ステップ2・3 の規定を、プロジェクト向けに読み替えて `template/CLAUDE.md` ステップ2・3 に追記する（記録5項目・確認できない候補の扱い・読み替え置換の理由を同じ構造で書く） | 採用 | 両リポジトリで同じ規定・同じ記録項目になり、還元と取り込みで README の構造が揃う。テンプレート側の案件 README（update-004 以降は「目的・背景」節あり）が典拠として使える |
| A | ステップ2 に「テンプレート側の案件 README を読む」の1文だけ足す | 不採用 | update-011 の失敗は README の要約を読んでも起きた。design.md の改訂履歴と reviews/ まで読む範囲を明示し、記録項目を固定しないと Codex が適合を判定できない |
| B | 精査規定を新しい基準書（例: `docs/INTAKE_STANDARD.md`）に切り出す | 不採用 | 内容は2行の追記で収まる。基準書を増やすと update フローとの参照が二重になる |
| C | 取り込み対象をテンプレートに限定し「他リポジトリの運用の取り込み」を含めない | 不採用 | プロジェクト間で直接取り込む実績がある（lift2d update-001 は本リポジトリ経由だが、honOCR の調査結果を lift2d update-005 が直接参照した例がある）。反映元の種類で規定を分ける理由がない |

### 保持すべき制約（本案件で変えないこと）

- ステップ2 の既存文（変更理由の記録義務、還元時の典拠になる旨）、ステップ3 の既存文（自己完結・曖昧表現禁止・全置換の後処理・完了処理を設計に含める）は残す
- 記録5項目 (a)〜(e) と「確認できない候補は推測で補わない」の文言は、ルート `CLAUDE.md` ステップ2（update-012）と同じにする。(d) だけ「汎用化で変えてはいけない部分」→「本プロジェクト向けの読み替えで変えてはいけない部分」に読み替える
