# update-009: honOCR のプロジェクト知識の外出し（統治と知識の分離）をテンプレートへ取り込み

## ステータス

Closed（2026-09-04 起票・完了）

## 目的・背景

honOCR の update-003（プロジェクト知識を `CLAUDE.md` から `docs/PROJECT_KNOWLEDGE.md` へ分離）で確立した構造を、テンプレートへ取り込む。

`CLAUDE.md` には性質の異なる2種類の内容が同居している。

| 種類 | 内容 | 更新する主体 |
|---|---|---|
| **統治** | 開発フロー・レビュー手順・運用ルール・コーディング規約 | update 案件のみ |
| **知識** | データの所在と仕様・ディレクトリ構成・ドメイン知識・技術スタック要約 | feat/bug 案件の完了処理 |

同居しているため、案件で得た知見を追記するという日常的な操作が、毎回「統治文書の編集」になる。honOCR ではこの構造が「`CLAUDE.md` への正当な編集が頻繁にあるため、不適切な編集が紛れても目立たない」という問題を生んだ（feat-018 のインシデント調査で顕在化）。分離すれば知識ファイルへの追記は統治への干渉ではなくなり、「`CLAUDE.md` を変更する」行為そのものが稀な例外イベントになる。

honOCR は `CLAUDE.md` を変更した全17コミットを機械集計し、feat 案件が更新したのは知識4セクション（ドメイン知識9回・ディレクトリ構成6回・データ5回・技術スタック2回）のみで、統治部分への feat の更新は **0回**であることを実測した。分離線は運用実態として既に存在しており、それをファイル境界に昇格させたのが honOCR update-003 である。

この構造は honOCR 固有の事情に依存しない。本テンプレートで開発するどのプロジェクトでも、feat/bug 案件は知識を更新し統治は更新しないため、同じ分離が成立する。
