### 項目1 を高優先度とする理由（本リポジトリ自身の穴でもある）

`template/CLAUDE.md` は update-008 で全文ゲート（C）の上限単位を「レビュー単位」に変更したが、
**レビュー単位の同一性を定義していない**。そのため、同じ文書一式を初回レビュー（A）に指定し直せば
「新しいレビュー単位」を名乗ることができ、C を何度でも実施できてしまう。これは update-008 が
明文化した1回ゲート型（「同じ文書一式に『新しい目』を2回使わない」）の趣旨を無効化する。

さらに、本リポジトリのルート `CLAUDE.md`「テンプレート改訂フロー」ステップ4 は、レビュー手順を
二重管理せず `template/CLAUDE.md`「Codexによるレビューの実行方法（Herdr 対話方式）」の
「レビューの進め方」（「収束」の定義を含む）を読み替え適用している。したがって
**この抜け穴は DEV_TEMPLATE 自身の update 案件レビューにも現に存在する**。本案件の反映により、
テンプレートと本リポジトリの運用の両方が同時に修正される。

## 反映対象の選別と理由

### 反映する（3件すべて）

**項目1【高】レビュー単位の同一性を定める1文**

- 汎用性: あり。レビュー運用のルールであり、言語・ドメインに依存しない
- 理由: update-008 で導入した1回ゲート型の抜け穴の塞ぎ込み。本リポジトリ自身の運用にも同じ穴がある（前述）
- honOCR 側の文面をそのまま採用する（テンプレートと honOCR の当該節は、この1文以外は一字一句同一のため）

**項目2【中】環境を変更する操作の事前承認ルール**

- 汎用性: あり。プロジェクト非依存の運用ルール
- 理由: honOCR ではテンプレート導入コミット `92d60db` の時点から存在し、以後も維持されている実績のあるルール
- **ただし文面はそのまま転記しない**。honOCR の例示「モデルのダウンロード」は機械学習プロジェクトを
  前提とした読みになる。ルート `CLAUDE.md`「テンプレート保守の方針」の
  「プロジェクト固有の記述（ドメイン知識・特定ライブラリ等）は `template/CLAUDE.md` に持ち込まず、
  プレースホルダまたは汎用例に留める」に従い、例示を汎用化する（具体は design.md §3.2）

**項目3【低〜中】`README.md` にローカルの実パスを書かない**

- 汎用性: 条件付きであり。実パスを書かない理由は「公開リポジトリのため」であり、
  テンプレートは公開・非公開のどちらのプロジェクトにも使われる
- 理由: 公開リポジトリでの運用は珍しくなく、規定があること自体に価値がある
- **honOCR の文面（理由を「公開リポジトリのため」と断定）はそのまま転記せず、条件付きにする**（具体は design.md §3.3）
- 補足（本リポジトリでの調査で判明）: `template/` には `README.md` の雛形が存在しない
  （`CLAUDE.md` / `AGENTS.md` / `.gitignore` / `docs/*` のみ）。ただし既存のステップ8 も雛形なしで
  `README.md` の更新に言及しており、本追記によって新たな不整合は生じない。雛形の新設は本案件のスコープ外とする

### 反映しないもの

| 対象 | 理由 |
|---|---|
| `CLAUDE.md` のその他の差分 | すべて `{{ }}` プレースホルダ部分（プロジェクト概要・目標・背景・技術スタック節の言い回し・ドメイン知識の例示・ストリーム命名の略称・テスト実行コマンド・コーディング規約）。テンプレート側が意図的に穴埋め形式にしている箇所 |
| `.gitignore` の差分 | honOCR 側の追加は Python/uv（`.venv/`・`__pycache__/`・`*.pyc`）と OCR 成果物（`output/`）のみで、いずれも言語・ドメイン依存。テンプレートの `.gitignore` は言語非依存な最小構成を意図している |
| honOCR の `docs/PROJECT_KNOWLEDGE.md` の内容 | プロジェクト固有の知識 |
| honOCR codex-02 の併記提案（結果メタにレビュー単位の識別子を追加） | honOCR 側でユーザーが不採用と決定済み（2026-09-04）。テンプレート側でも採用しない |
| `template/README.md` 雛形の新設 | 本案件のスコープ外（項目3 の追記は雛形なしでも成立する）。今後の拡張候補 |

## 案件の切り方

3件を1案件にまとめる。理由:

- 変更先はすべて `template/CLAUDE.md` の1ファイルで、いずれも数行の追記
- 前例（update-008 は `CLAUDE.md` 2箇所の置換で1案件、update-005・update-006 も単一トピックで1案件）に照らして粒度は妥当
- 分割すると Codex レビュー（A→B→C）を3セット回すことになり、変更量に対して過剰
- 由来の違い（項目1 は update-004 由来、項目2・3 は以前からの未還元）は本 README への記録で足りる
