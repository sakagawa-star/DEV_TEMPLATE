## 調査結果

### 反映元の新規ルール（lift2d update-002）

lift2d の feat-026（外部パラメータ自動リファイン）で試験導入され、update-002 案件（lift2d コミット b9f2a17 で起票・0539655 で完了）で `CLAUDE.md` に正式ルール化されたもの。内容は以下の4項目と適用範囲の定義:

1. **判定基準の事前定義**: 実験実行前に「答える問い」「判定閾値」「合格ライン」を数値で criteria 文書に定義し、Codex レビューを重要度「高・中」ゼロまで収束させてから実験に着手する（criteria lock）
2. **直前予測**: 各フェーズの実行直前に数値予測を実験ログに記録してから実行する（予測は前段の実測を使って直前に立てる）
3. **照合**: 実行後に予測と実測を照合し、乖離時は原因を特定してから次フェーズへ進む
4. **事後解釈の禁止**: 結果を見てから合格ラインを定める・事前基準にない条件を付けて合格扱いにする（事後解釈での Go/No-Go 判定）を禁止

適用対象は「数値判定を伴う実験・検証」に限定（通常の実装・自動テスト・数値判定を伴わない調査は対象外）。

導入の経緯（lift2d update-002 README.md より）: 判定基準のない実験を実行し結果を事後解釈で「条件付きGo」とした事例が起点。以降の全実験で本プロトコルを適用して有効性が確認され、正式ルール化された。

### 差分1の汎用化調整（テンプレートとしての要修正点）

lift2d の節本文をそのまま持ち込むとプロジェクト固有記述が混入するため、以下の3点を調整する:

1. **出自注記の削除**: 「（feat-026 で試験導入し確立した運用。2026-07-31〜08-02）」は lift2d 固有の履歴のため削除する
2. **pytest の汎用化**: 対象外の説明「pytest はテストコード自体が期待値＝予測の文書化に当たる」の「pytest は」を「自動テストは」に置き換える（テンプレートの他箇所と同じ汎用化方針）
3. **実例参照の削除**: 「実運用の例は `docs/issues/feat-026-render-match-extrinsic-refinement/experiments/` の criteria 文書・experiment_log.md を参照。」は、新規プロジェクトには存在しないパスへの参照切れになるため削除する

挿入位置（「ドキュメント更新フロー（update-XXX 案件）」の「#### 運用メモ」直後、「### ドキュメント作成ルール」直前）は、テンプレートにも同一のアンカーが存在するため lift2d と同じ位置に挿入できる。
