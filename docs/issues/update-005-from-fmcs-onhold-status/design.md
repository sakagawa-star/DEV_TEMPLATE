# update-005 反映設計書: fmcs-utils のステータス凡例（On Hold 含む）をテンプレートへ取り込み

## 1. 概要

`template/docs/BACKLOG.md` に `## ステータス凡例` 節を新設し、fmcs-utils で確立した6ステータス（Open / In Progress / Review / On Hold / Closed / Cancelled）の定義を取り込む。あわせて記入例コメント内の旧ステータス行を凡例参照に変更する。

- **変更方式**: 既存テキストの部分置換・節追加（全置換なし。後処理なし）
- **実装者**: 「実装の実行方法（Sonnetサブエージェント）」の読み替え（本リポジトリ CLAUDE.md「テンプレート改訂フロー」ステップ5）に従い、Sonnet サブエージェントが design.md 準拠で反映する
- **テスト**: 不要（コード変更なし。自動・手動とも実施しない）

## 2. 変更対象ファイルと変更内容

変更対象は `template/docs/BACKLOG.md` の1ファイルのみ。

### 変更1: 記入例コメント内のステータス行の置換

記入例 HTML コメント内の次の1行:

```
ステータス: Open / In Progress / Closed
```

を、次の1行に置換する:

```
ステータス: 「ステータス凡例」の節を参照。
```

### 変更2: `## ステータス凡例` 節の新設

ファイル末尾（記入例 HTML コメントの閉じタグ `-->` の後）に、空行を挟んで次の節を追加する:

```
## ステータス凡例

- **Open**: 起票済み・未着手
- **In Progress**: 調査・実装中
- **Review**: レビュー中
- **On Hold**: 一時中止（凍結）。再開する場合も、そのまま中止する場合もある。On Hold にする際は、本表の備考に日付・理由・再開点を記録し、案件フォルダの README.md のステータスも On Hold に更新する（README.md が未作成の案件では、概要と現在のステータスを記した README.md を作成して記録する）
- **Closed**: 完了
- **Cancelled**: 取りやめ・破棄（ドキュメントは履歴として残す）
```

凡例の文言は fmcs-utils `docs/BACKLOG.md`（コミット `8868925`）の同節を基にする。ただし On Hold の行末の括弧書きはテンプレートでの追加である: feat フローは案件 README.md の作成を必須としていないため、そのまま転用すると更新対象の README.md が存在しない案件があり得る。この適応の経緯は本案件 `README.md` の「テンプレートへの適応」を参照。他の文言はプロジェクト固有記述を含まないため改変なしで転用する。

## 3. 実施手順

1. 変更1・2 を上記のとおり適用する
2. 反映直後の検証を行う（4章）
3. 完了処理を行う（5章）

設計にない変更が必要になった場合は中断し、調査（テンプレート改訂フロー ステップ2）に戻る。

## 4. 反映直後の検証（完了処理の前）

1. `git diff template/docs/BACKLOG.md` の差分が、変更1の1行置換と変更2の節追加**のみ**であることを確認する
2. `template/` 配下の他ファイルに差分がないことを `git status --short template/` で確認する
3. `grep -n "Open / In Progress / Closed" template/docs/BACKLOG.md` が0件であることを確認する（旧ステータス行の消去確認）

## 5. 完了処理（4章の検証に合格し、人レビューを通過してから実施する）

Claude Code 本体が行う:

1. 本案件 `README.md` の `## ステータス` 節の本文を `Closed（2026-08-27 起票・完了）` に置き換える
2. ルート `CLAUDE.md` のディレクトリ構成: ファイルの追加・削除はないため、`docs/issues/` 配下の案件例示に変更が必要かのみ確認する（既存の記述形式では案件フォルダは例示1件のみのため、変更不要の見込み）
3. git 操作（コミット）は本リポジトリ CLAUDE.md の運用ルールに従い Opus サブエージェントに委任する

## 6. テスト

コード変更がないため、テスト（自動・手動とも）は不要。
