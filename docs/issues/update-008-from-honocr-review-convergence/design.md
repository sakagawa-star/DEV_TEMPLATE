### 2.4 旧ルール5「指摘が出たら」の重要度の確定（解釈の根拠）

旧ルール5 は「ゲートで指摘が出たら: 全件まとめて反映し…」と書かれ、指摘の重要度を区別していない。字義どおり読むと「低のみの指摘」でも反映と解消確認が必要になるが、この読みは同じ手順内の他規定と矛盾する。

1. 旧ルール2 は反映対象を「高・中の指摘」と限定している（低の反映を義務づけていない）
2. 旧ルール3 は反復の終了条件を「高・中ゼロになるまで」、旧ルール4 は全文ゲートへの移行条件を「高・中ゼロになったら」と定めており、手順内の判定はすべて高・中で行われている
3. 旧ルール6 は「全文ゲートで高・中ゼロが出たら人レビューに進む」であり、低が残っていても人レビューへ進む規定である

したがって既存規則の意図は「反映義務は高・中のみ。低は収束判定に影響しない」であり、置換後の遷移表はこれを「高・中が1件以上 / 高・中ゼロ」と明示する。**解釈の確定であって規則の変更ではない。** なお `template/docs/REVIEW_CRITERIA.md` §2.2「修正対象」（高・中を修正対象、低は報告のみ）はコードレビュー配下の規定であり、本解釈の根拠には使わない（同文書は変更しない）。

### 2.5 旧ルール4・6 の収束の読みの確定（1回ゲート型。解釈の根拠）

旧ルール4「高・中ゼロになったら `/new` を送って…」と旧ルール6「全文ゲートで高・中ゼロが出たら人レビューに進む」は、次の2つの読みを許している。

- **ループ型**: 解消確認のゼロのたびにルール4 が再発動する。収束はゲート自身のゼロのみ
- **1回ゲート型**: 「新しい目」のゲートは案件につき1回。ゲートの指摘は同一会話の解消確認で閉じ、その会話で高・中ゼロに達したら収束

本改訂は **1回ゲート型**を採用する（2026-08-31 ユーザー決定。「レビューの『新しい目』は1回限り。2回目は使わない」）。根拠:

1. **ループ型は終了が保証されない。** 「新しい目」は会話の記憶を持たない別のレビュアーであり、毎回新しい指摘を見つけうる。honOCR update-002 のレビュー実測: 1回目のゲートで2件 → 全件反映後の2回目のゲートで別の2件
2. 旧ルール5 が「同じ会話（`/new` はしない）で解消確認を依頼する」と明記しており、ゲート後の処理を同一会話で閉じる設計と整合する
3. 本テンプレートを同一内容で運用する他リポジトリの実運用と整合する（ユーザー確認）

### 2.6 C の上限単位を「レビュー単位」とする（honOCR 版からの変更点と根拠）

honOCR 版は C を「案件（細分化して並列に進める場合は細分化単位）につき1回だけ」としている。しかし `template/CLAUDE.md` の「実験・検証の進め方」（criteria lock、131行目）は、同一案件内で criteria 文書に対しても Codex レビューと高・中ゼロへの収束を要求し、結果を案件の `reviews/` に連番を進めて保存すると定めている。honOCR 版の文言のままでは、案件のステップ4 のレビューで C を使った後、criteria 文書のレビューで C を行えず（「案件につき1回」に抵触）、「逸脱の禁止」により別サイクルを始めることもできない。新規プロジェクトで実験案件が運用不能になる（codex-01 の指摘・高）。

そこで C の上限単位を「レビュー単位」（初回レビュー A で対象ファイルとして指定した文書一式）と定義し、案件のステップ4 のレビュー対象・細分化単位・criteria 文書をそれぞれ別のレビュー単位とする。案件のステップ4 のレビューと細分化単位については honOCR 版と同じ動作であり、criteria 文書についてのみ「別のレビュー単位として A から始める」ことを明示した。honOCR 版の「1回ゲート型」の趣旨（同じ文書一式に「新しい目」を2回使わない）は変わらない。
