## ステータス

## 目的・背景

honOCR の update-002（Codex レビュー手順の収束条件を誤読不能な形に改訂）で確立した記述を、テンプレート `template/CLAUDE.md` へ取り込む。

`template/CLAUDE.md` の「Codexによるレビューの実行方法（Herdr 対話方式）」配下「レビューの進め方」（ルール1〜6）は、全文ゲート（`/new` による「新しい目」）を**1回だけ**行うのか、解消確認が高・中ゼロになる**たびに**再発動するのかを特定していない。honOCR ではこの曖昧さが顕在化し（ゲートが指摘を返した場合に2つの読みが異なる動作になる）、当時の Claude Code が曖昧さを自覚しながらユーザーに確認せず独自解釈で人レビューへ進んだ。honOCR の update-002 は、(1) 収束ルールを **1回ゲート型**（全文ゲートは案件につき1回。ゲートの会話で高・中ゼロに達したら収束）として一意に明文化し、(2) 解釈で迷った場合の行動（作業を止めてユーザーに確認する）を「逸脱の禁止」として規則化した。

honOCR 側では、全文ゲートを繰り返すたびに新しい指摘が出続ける（1回目のゲートで2件 → 反映後の2回目のゲートでさらに別の2件）ことが運用実測で確認されており、ループ型では収束が保証されない。ユーザーは意図された規則を1回ゲート型と確定している（2026-08-31）。

honOCR の当該記述はテンプレートから update-001（honOCR 側）で取り込んだものであり、honOCR の update-002 README §8 で「テンプレート側への還元を検討する」と記録されている。本案件はその還元である。

### 取り込み時に修正する点（Codex レビュー codex-01 の指摘・高）

honOCR 版は全文ゲート（C）を「案件（細分化して並列に進める場合は細分化単位）につき1回だけ」としている。しかし `template/CLAUDE.md` の「実験・検証の進め方」（criteria lock、131行目）は、同一案件内で criteria 文書に対しても Codex レビューと収束を別途要求する。honOCR 版の文言のままでは、案件のステップ4 のレビューで C を使った後に criteria 文書の C を行えず、「逸脱の禁止」により別サイクルも始められない。本案件では C の上限単位を「レビュー単位（初回レビュー A で対象ファイルとして指定した文書一式）」と定義し、案件のステップ4 のレビュー対象・細分化単位・criteria 文書をそれぞれ別のレビュー単位として取り込む（design.md 2.6）。honOCR 版との差分はこの2行のみで、「1回ゲート型」の趣旨は変わらない。

### 本リポジトリ（DEV_TEMPLATE）自身の運用への影響

ルート `CLAUDE.md` の「テンプレート改訂フロー」ステップ4 は、`template/CLAUDE.md` のレビュー節を読み替えで適用する規定であり、「反復レビュー→`/new` 全文ゲート、重要度「高・中」ゼロ収束→人レビューの順序はそのまま従う」と旧ルールの構成語で書かれている。取り込み後は「レビューの進め方」の構成が変わるため、この一文を新構成（「収束」の定義・遷移表・人レビューの前提・逸脱の禁止・結果の保存の冒頭メタ）に合わせて更新する（完了処理で Claude Code 本体が行う）。規則の内容は変わらない。
