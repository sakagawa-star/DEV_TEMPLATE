# update-012: テンプレートへの取り込み時に「経緯と目的」の精査を必須化する（取り込み元の記録義務と、update 案件の反映の Sonnet 委任化を含む）

## ステータス

Closed（2026-09-06 起票、2026-09-07 完了。Codex レビュー7回で高・中ゼロ収束〔全文ゲート codex-03 後、人レビュー2回の指摘反映を含め codex-07 で収束〕、人レビュー承認済み、design.md どおり反映・検証済み）

## 概要

他リポジトリの開発ドキュメントをテンプレートへ取り込む際、反映元の最終ファイルの差分だけを見て選別・汎用化するのではなく、
**「なぜそのドキュメント（規定）を使うようになったか。その形式にした経緯と目的」を反映元の案件文書から精査してから還元する**ルールを作る。
あわせて、取り込み元となる各プロジェクト側にも、update 案件の README に経緯（契機・目的・採らなかった案）を必ず残す義務を入れ、
テンプレート側の精査が常に典拠を辿れるようにする。

変更対象は4箇所（#1〜#3 はユーザー採用 2026-09-06、#4 は人レビュー 2026-09-07 で追加）:

| # | 対象 | 変更 |
|---|---|---|
| 1 | ルート `CLAUDE.md`「テンプレート改訂フロー」ステップ1〜3 | slug の規定を反映元の有無で分ける。経緯と目的の精査を必須化し、README に記録する項目（契機・目的・形式の理由・保持すべき制約・典拠）を固定する。確認できない候補は推測で補わない。汎用化の置換は1件ごとに制約を損なわない理由を design.md に書く |
| 2 | ルート `AGENTS.md` の規定適合確認の項目 | README / design.md の必須内容の列挙を止め、「ステップ2 / 3 が定める内容」として `CLAUDE.md` を情報源に参照させる（二重管理の解消。#1 の追加が自動的に判定対象になる） |
| 3 | `template/CLAUDE.md`「ドキュメント更新フロー」ステップ2 と運用メモ | update 案件の README に契機・目的・採らなかった案（人レビューでの方針転換を含む）を必ず書く。還元時にこれが精査の典拠になる旨を運用メモに添える |
| 4 | `template/CLAUDE.md`「ドキュメント更新フロー」ステップ5 と「実装の実行方法」冒頭 | 「実装は Claude Code 本体が行ってよい（オーバーヘッドに見合わないため）」の但し書きを削除し、update 案件の反映も無条件に Sonnet 委任にする（読み替えを明記）。「実装の実行方法」の適用範囲に同ステップを加える |

## 背景・変更理由

### 契機（update-011 で起きたこと。2026-09-06）

update-011 で lift2d の `AGENTS.md` の規定適合確認（案件文書が CLAUDE.md の規定に適合するかを Codex に判定させ、一意に決まらなければ
「判定不能」を高で報告させる項目）をテンプレートへ取り込む際、Claude Code は反映元の最終ファイルと案件 README の要約だけを読み、
`design.md` の改訂履歴と `reviews/`（codex-03〜05 で「判定が決定論的でない」指摘が続き、行き詰まり検出を発動して
「規定を AGENTS.md に再掲せず、所在を指定し、決まらなければ判定不能を報告させる」形に至った経緯）を読んでいなかった。
その結果「本リポジトリでは判定不能・高が出続けて収束しない」ことを不具合と誤認し、**設計の要である検査そのものを外す案（ルート `AGENTS.md` を旧版のまま据え置く）を推奨した**。
ユーザーの指摘（「lift2d の AGENTS.md がなぜこのような内容になったかをまず理解しなさい」）で経緯を読み直し、
「判定不能・高」は規定の穴を表面化させる設計上の信号であり、対処は参照先を本リポジトリの規定に合わせることだと理解を改めた
（update-011 README「留意事項 A」）。

### 契機2（人レビュー 2026-09-07。#4 の追加）

本案件の design.md 初版は D3・D4 を「行内置換2件のみで Sonnet 委任のオーバーヘッドに見合わない」として本体が行う例外を置いていた。人レビューで「Sonnet 委任の理由を超えるメリットがあるのか」と問われ、ないと判断して撤回した。
その際、同じオーバーヘッド基準の但し書きが `template/CLAUDE.md` ドキュメント更新フロー ステップ5 に残っていることを報告したところ、ユーザーから「消させたはずなのに、なぜ残っているか」の指摘があった。履歴を確認した結果:

- 但し書きは update-002（SynchroCap 由来、コミット `715db11`、2026-07-30）で入り、以後変更されていない
- lift2d update-007（2026-09-04）は feat ステップ6 の「製品コード」免除条項を削除したが、README 調査2 で「update 案件の反映（ドキュメント更新フロー ステップ5）は変えない」とスコープを限定していた
- 本リポジトリ update-010（2026-09-05）は、design.md がこの但し書きを根拠に本体実施としたのを Codex 全文ゲート（codex-03）が「ルート `CLAUDE.md` ステップ5 は Sonnet 委任であり根拠にならない」と指摘して案件文書を直したが、`template/CLAUDE.md` の但し書きは残った
- 本リポジトリのルート `CLAUDE.md`「テンプレート改訂フロー」ステップ5 は当初（`5b5569c`）から無条件に Sonnet 委任で、但し書きはない

ユーザー判断（2026-09-07）: 本案件に含めて削除する（#4）。

### 目的

- 取り込みの選別と汎用化の判断を、反映元の**目的**に照らして行えるようにする（差分の表面だけで「不要」「言い換え可」と判断しない）
- 「経緯が分からないものは取り込まない」を規則にし、推測で目的を補うことを禁止する（`AGENTS.md` の「判定不能」と同じ思想）
- 取り込み元のプロジェクト側に経緯の記録を義務づけ、テンプレート側の精査が常に典拠を辿れる状態を作る
- update 案件の反映も feat / bug の実装と同じく無条件に Sonnet 委任とし、「変更量が小さいから本体でよい」という条件分けをテンプレートから除く（委任の目的は design.md の自己完結性の独立検証であり、変更量と無関係。lift2d update-007 と同じ理由）

### 形式の理由と採らなかった案

| 案 | 内容 | 判断 | 理由 |
|---|---|---|---|
| **採用** | ルート `CLAUDE.md` ステップ2 に精査の手順と記録項目（5項目）を書き、ルート `AGENTS.md` は `CLAUDE.md` を参照するだけにする。`template/CLAUDE.md` 側に記録義務を入れる | 採用 | 規定は `CLAUDE.md` にだけ置き、`AGENTS.md` は所在を指す（lift2d update-006 の設計思想）。記録項目を固定することで Codex が存在を機械的に判定できる。取り込み元にも義務を置くことで典拠が必ず残る |
| A | 案件 README の雛形（チェックリスト）を `docs/issues/` に置くだけにする | 不採用 | 雛形は規則にならず、Codex の適合判定の情報源にもならない（ルート `CLAUDE.md`「未テンプレート化」の案件テンプレートは別件） |

| C | テンプレート側（本リポジトリ）だけを変え、取り込み元への記録義務（#3）は入れない | 不採用 | 反映元に経緯の記録がなければ精査できず、#1 の「確認できない候補は取り込まない」が頻発する。lift2d の update-005〜007 は事実上「背景・変更理由」「採らなかった案」を書いており、それが update-011 の精査を可能にした。規則化して全プロジェクトに揃える |

- 「定型指示は `AGENTS.md`、案件種別固有の観点は依頼文」の原則を変えない

### 既存案件での記録の実態

- 本リポジトリの update 案件 README: update-004〜010 は「目的・背景」節を持つ。update-001〜003 と update-011 は「概要」のみ（update-011 は候補ごとに「汎用性の判断」を書いたが、契機・採らなかった案・保持すべき制約は書いていない）
- lift2d の update-005〜007 は「背景・変更理由」節（契機・ユーザー指示・人レビューの差し戻し記録）と「採らなかった案」の表を持ち、design.md の改訂履歴に Codex 指摘ごとの対応理由がある。本案件の精査手順はこの実態を規則化したもの

### 影響

- 本案件のレビューは、update-011 で反映したルート `AGENTS.md` の規定適合確認（参照先: テンプレート改訂フロー）が有効になってから最初の Codex レビューであり、update-011 design.md「6. 動作確認」を兼ねる（「[AGENTS.md適用]」マーカーと適合判定の有無を確認する）
- 本案件の README は、自らが定める5項目（契機・目的・形式の理由・保持すべき制約・典拠）を「背景・変更理由」節と「反映元」節で満たしている
- 取り込み元のプロジェクト（lift2d・honOCR 等）には、次回テンプレートを取り込む際に #3 が反映される。既存案件への遡及は求めない

## 反映しないもの

- 案件 README の雛形ファイルの新設（「未テンプレート化」の案件テンプレートは別件）
- `template/AGENTS.md` の変更（規定適合確認の項目は「CLAUDE.md のフロー節と参照先の規定」を参照する形で既に再掲がなく、#3 の追加は自動的に判定対象になる）
- 既存案件 README の遡及修正
