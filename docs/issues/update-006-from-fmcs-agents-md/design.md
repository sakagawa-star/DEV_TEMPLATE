# update-006 反映設計書: fmcs-utils の AGENTS.md によるレビュー定型指示の永続化をテンプレートへ取り込み

## 1. 概要

`template/AGENTS.md` を新規作成し、`template/CLAUDE.md` のレビュー依頼文から定型指示を削って「対象ファイル＋案件種別ごとの基準・観点の指定」に短縮する。あわせて、定型指示の供給元・適用マーカーの確認手順・`resume` セッションへの非反映の注意を明記する。

- **変更方式**: 新規ファイル1件＋既存テキストの部分置換・行追加（全置換なし。後処理なし）
- **実装者**: 「実装の実行方法（Sonnetサブエージェント）」の読み替え（本リポジトリ CLAUDE.md「テンプレート改訂フロー」ステップ5）に従い、Sonnet サブエージェントが design.md 準拠で反映する
- **テスト**: 自動テストは不要（コード変更なし）。ただし本案件が導入する運用上の契約（コピー先の新規リポジトリで Codex が起動時に `AGENTS.md` を読むこと）は静的検証では保証できないため、4章の検証5（実機確認・手動）で確認する

### 2.2 `template/CLAUDE.md` — 定型指示の供給元の明記

「### Codexによるレビューの実行方法」節の第2段落

> 使用するモデルは `~/.codex/config.toml` のデフォルト設定に従う。本ファイルのコマンドにはモデル指定（`-m`）を書かない。モデルを切り替えたい場合は `~/.codex/config.toml` を編集する（全プロジェクト共通で反映される）。

の直後に、空行を挟んで次の段落を挿入する:

```
定型指示（瑣末な指摘の抑止・重要度(高/中/低)分類・修正提案の要求・適用マーカー）はリポジトリ直下の `AGENTS.md` が起動時に供給するため、**依頼文には書かない**。AGENTS.md はセッション開始時にのみ読み込まれるため、変更しても `resume` で継続中のセッションには反映されない（新規の `codex exec` から有効になる）。
```

### 2.3 `template/CLAUDE.md` — 「出力の保存（結果と過程を分離）」にマーカー確認を追加

「#### 出力の保存（結果と過程を分離）」の箇条書き末尾（「`result.md` には Codex の生出力に加え、…」の項目の後）に、次の1項目を追加する:

```
- **`result.md` を読む際は冒頭の「[AGENTS.md適用]」マーカーを毎回確認する**。マーカーが無い場合は `AGENTS.md` の適用を確認できないため、その結果を採用せず、新規セッション（`resume` ではない新しい `codex exec`）で再実行する。再実行でもマーカーが出ない場合は、`AGENTS.md` の配置（リポジトリ直下にあるか）・起動ディレクトリ・Codex CLI の設定を確認し、ユーザーに報告する。
```

### 2.4 `template/CLAUDE.md` — 依頼文の短縮（4箇所）

コマンド例4つの依頼文から定型指示を削除する。コマンドの他の部分（`mkdir -p`、`-o`、リダイレクト等）は一切変えない。

1. **「#### 初回レビュー（機能追加の場合）」**のコマンド内依頼文を次に置換する:

   ```
   "docs/REVIEW_CRITERIA.md の基準に従い、以下のドキュメントをレビューせよ: docs/issues/{案件フォルダ}/requirements.md docs/issues/{案件フォルダ}/design.md 。"
   ```

2. **「#### 初回レビュー（不具合修正の場合）」**のコマンド内依頼文を次に置換する:

   ```
   "docs/REVIEW_CRITERIA.md および docs/BUGFIX_STANDARD.md の基準に従い、以下のドキュメントをレビューせよ: docs/issues/{案件フォルダ}/investigation.md 。requirements.md / design.md を変更した場合はそれらもレビュー対象に含めること。"
   ```

3. **「#### 初回レビュー（ドキュメント更新の場合）」**のコマンド内依頼文を次に置換する:

   ```
   "以下のドキュメントをレビューせよ: docs/issues/{案件フォルダ}/README.md docs/issues/{案件フォルダ}/design.md 。レビュー観点は次の3点: (1) 反映計画の自己完結性（design.md だけで作業ができるか） (2) 情報の喪失（削除・置換対象に、他所に存在しない情報が含まれていないか） (3) 変更後のドキュメント間整合性（参照切れ、矛盾、案件の漏れ・重複）。"
   ```

4. **「#### 再レビュー（共通）」**のコマンド内依頼文を次に置換する:

   ```
   "ドキュメントを更新したので再レビューして。前回と同じ基準で。前回指摘が解消されたかを含めて確認して。"
   ```

いずれも削除するのは定型指示（「瑣末な点へのクソリプはしないで、致命的な点のみ指摘して。」「発見した問題を重要度(高/中/低)で分類し、修正提案とともに報告すること。」「重要度(高/中/低)で分類し、修正提案とともに報告すること。」）のみであり、対象ファイル・基準・観点の指定はすべて残す。
